# v1.0.3 compatibility and security

This candidate is unsigned. SHA-256 checks identify the supplied files; they do not provide Authenticode publisher verification. See the release notes for qualification and compatibility scope.

## Authentication

The website deliberately retains OpenSim/DreamGrid's `md5(md5(password) + ':' + salt)` compatibility. It does not upgrade OpenSim password storage or change existing accounts. HTTPS is strongly recommended for every internet-facing grid, especially for powerful admin operations. Configure TLS separately; the installer does not change certificates, DNS, native ports or Apache TLS.

Login and logout cookies use HttpOnly, SameSite=Lax and Secure when Apache reports HTTPS. The signed session expires after eight hours; protected requests recheck the account's current database level. Existing same-origin/CSRF checks remain in place. HTTPS detection does not trust arbitrary forwarding headers. A TLS-terminating reverse proxy requires an explicitly trusted server configuration; merely forwarding a client-supplied HTTPS header is insufficient.

Both Other and API credential endpoints share throttle counters, so alternating endpoints does not bypass protection. API cookie scope and its separate existing signing secret are retained. New API cookies include signed issue/expiry timestamps, and the API verifier now enforces them. Existing legacy API sessions without signed timestamps must log in again; accounts/passwords and API functionality are preserved. Other cookies already contained and validated these timestamps.

Login attempts reserve server-side counters under a bounded file lock before database verification. State resides in the existing web-blocked `private/login-throttle` area. An account/source pair begins temporary throttling after three failures; a source across accounts begins after ten. Delays grow from one second to at most sixty seconds. Rejected requests never extend deadlines. Five minutes without an accepted attempt resets counters, and a successful login clears its pair penalty. Source counters retain other failures. Only REMOTE_ADDR is used; forwarded headers are ignored. Another source does not share an account-wide lockout. State holds at most 1,024 sources and 3,072 pairs, with stale entries pruned and oldest entries evicted. Account/source identities are HMACed with the existing session secret; passwords are never stored in throttle state. First-use secret creation is serialized and uses a temporary file inside the blocked private area, without replacing existing secrets.

Failures and nonexistent accounts retain the same generic login response. Temporary throttles return that same response with HTTP 429 and Retry-After. Storage failure fails closed with a generic HTTP 503. Local/LAN HTTP remains supported, with the protections available on HTTP; TLS remains recommended.

An admin network allowlist may be implemented by the grid operator as an optional deployment policy. This candidate enables no IP restriction, and remote admins with dynamic addresses remain supported. No account or session endpoint returns secret-existence or private filesystem state.

## Native integration transaction

The preserved bridge is `_WEB_CONTROL/DreamGrid.NativeBridge.StartupHook.dll`, loaded via `runtimeOptions.configProperties.STARTUP_HOOKS` in the parent `Start.runtimeconfig.json`. It supports native deregistration, permanent deletion and readiness checks. The bridge now targets .NET 9 with no package references and waits for the existing Start/FormSetup before entering socket code. DreamGrid registers its embedded dependency resolver during AppStart; socket telemetry can then use the native embedded DiagnosticSource 10.0.0.0. No dependency DLL or resolver is added.

Before writes, strict UTF-8 JSON parsing rejects invalid tokens, duplicate/ambiguous properties, unsupported property types and unsupported runtime targets. This bridge build requires DreamGrid .NET 9; this family check is not proof of DreamGrid API compatibility. Any DreamGrid upgrade requires startup and bridge feature requalification, because the bridge reflects into native methods and the existing FormSetup window.

Only the hook value or its containing missing property is inserted. Unrelated JSON characters, BOM and newlines are retained. Existing foreign hook order is retained; old references to this bridge are replaced with one exact destination path. An already-correct hook is not rewritten. Backups are copied and SHA-256 checked before deployment. Payload deployment/verification and fresh CMS selection precede runtime hook commit. The original runtime bytes must still match the plan, and the backup and installed hook DLL must still match their recorded hashes. A staged runtime file is parsed and checked before atomic replacement; the committed file is byte-verified, parsed and checked again. Failure runs the existing exact-file rollback, which verifies restored hashes.

Fresh installation stages and verifies the website before selecting CMS=Other / OtherCMS=Other. Existing website content uses the preservation/backup path. Runtimeconfig, website, generated metadata and changed settings are covered by the same transaction. Rollback restores original runtimeconfig and Settings bytes, restores overwritten website files and removes newly installed files into a preservation archive. Existing secrets, keys, logs and private state are excluded from payload replacement.

Missing, invalid or incompatible hook DLLs can fail before Initialize executes, so its internal catch cannot guarantee DreamGrid startup. The previous startup failure came from socket acceptance before DreamGrid registered its embedded dependency resolver. The corrected bridge passed isolated native startup and authenticated loopback health on the qualified .NET 9.0.20 installation. Only a clean DreamGrid A/B run can qualify actual startup, OTHER persistence, readiness, DEREGISTER and DELETE. Synthetic tests are not a substitute.

Install and configure DreamGrid first. The website installer discovers the DreamGrid installation; select and confirm the destination or use Browse. Use an ASCII Windows installation path, turn DIVA off, and retain Folder = Other. Existing websites require OTHER selected. Fresh installations do not need OTHER enabled beforehand: choose the fresh-install option so the installer deploys and verifies website content before selecting CMS=Other / OtherCMS=Other and committing the approved startup hook. Stop DreamGrid, regions and Apache before installation or rollback.

NativeBridge requires .NET 9 and is qualified on DreamGrid 7.2114 with .NET 9.0.20. Requalify other DreamGrid versions. The setup EXE bundles its own installer runtime; that does not replace DreamGrid's runtime requirement. The Windows installer is unsigned and may trigger SmartScreen / Unknown Publisher warnings. Verify published SHA-256 checksums. HTTPS is strongly recommended for internet-facing grids; production TLS and code signing are not claimed.
